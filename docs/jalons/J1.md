# Jalon 1 — compte rendu

## Fait

- Squelette `uv` / `ruff` / `pytest`, CLI `btlab` (typer), paquet `btlab` à la racine du dépôt.
- Configs validées par pydantic, avec erreurs claires : 14 instruments, `periods.yaml`
  (IS / OOS / HOLDOUT + chauffe dès 2009) et `data.yaml` (téléchargement, seuils qualité).
- Calendrier de séances en heure locale du marché, converti en UTC minute par minute (`zoneinfo`) ;
  jours fériés NYSE / Xetra via `exchange_calendars`.
- Téléchargement Dukascopy M1 BID + ASK via `dukascopy-node` 1.50.0 épinglé :
  - découpage mois × côté, cache brut et manifeste ;
  - mise à jour incrémentale sur des jours UTC complets, reprise après échec ;
  - Parquet par symbole et par année.
- Contrôle qualité sans réparation : statut et raison par jour, exclusions en intervalles UTC,
  rapport HTML autonome avec carte de couverture « heure de la semaine ».
- Chargeur `load_m1` avec verrou IS :
  - refus et journalisation de toute plage OOS / HOLDOUT ;
  - jetons vérifiés dans `registry/runs.db` ;
  - années protégées jamais ouvertes ;
  - contrôle qualité à jour exigé.
- Interface Streamlit sur 127.0.0.1 :
  - accueil : périodes, journal des accès ;
  - page « Données » : couverture, téléchargement en tâche de fond, détail qualité, ajout
    d'instrument.
- 87 tests, sans réseau. Ils couvrent les configs, les changements d'heure, le téléchargement
  (y compris le vrai sous-processus Node avec un faux CLI), chaque anomalie qualité, le verrou,
  la CLI, le rapport et les pages Streamlit.

## Constats en cours de route

- Avec `retries = 0`, dukascopy-node masque les erreurs réseau : fichier vide, code de sortie 0.
  Le schéma impose donc `retries ≥ 1`.
- Sans `--volumes`, dukascopy-node ne filtre pas les bougies « plates » de remplissage, ce qui
  masquerait les trous. L'option est toujours activée.
- Un jour coupé par le début ou la fin des données est « incomplet » et exclu, et non
  « invalide » avec un faux trou.

## Hypothèses

- Horaires de séance provisoires pour tous les instruments (`verified: false`).
- Jours fériés de l'or et du WTI : calendrier NYSE comme approximation du CME.
- Seuils qualité par défaut, à calibrer sur les vraies données.

## Limites

- Dukascopy est inaccessible depuis l'environnement de développement cloud. Aucune vraie
  donnée n'a donc encore été téléchargée : validation faite sur données synthétiques et CLI
  simulée. Le premier vrai téléchargement doit se faire sur le poste Windows.
- Le verrou est un garde-fou contre l'erreur, pas une barrière (le Parquet reste lisible à la main).
